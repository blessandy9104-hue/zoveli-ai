Trust & Transparency

Check the machine's work instead of trusting a summary.

The short version

Verified mathLocal always. Independent methods must agree, or the answer is withheld.
Audit recordsLocal always. Hash-chained JSONL on your disk; edits are detectable.
Memory and notesLocal always. SQLite database plus a Markdown mirror you can read anywhere.
TelemetryNone. Zoveli does not send usage analytics.
Cloud chatOpt-in. If you set a provider key, the chat text you send goes to that provider.

Zoveli never sends the math audit log, the SQLite memory database, or the Markdown vault to a model provider. The memory brief is added to chat only for a local model by default; a cloud provider gets it only when you set ZOVELI_MEMORY_TO_CLOUD=1.

Provider keys are read from the environment and are not written into the vault. Your provider's retention and training policies still apply to the chat text you send it.

Audit logs you can inspect

Every verified, withheld, or mismatched computation can append to MATHCORE_AUDIT (default ~/.mathcore/audit.jsonl). Each record links to the previous one with a hash.

# Show recent certificate entries
mathcore verify-log --audit ~/.mathcore/audit.jsonl

# Check a claim; the verdict is appended to the same log
mathcore check "evaluate 6*7" "41"

# JSON for scripts and dashboards
mathcore --json "evaluate 6*7"

pnpm health:check summarizes config, vault, and MCP state. /trace in the CLI and the desktop status panel show recent tool calls.

Claim verification is pluggable

audit_claim() checks a proposed answer before Zoveli repeats it. Built-in verifiers run in order, then verified math is the fallback:

  • code — parses fenced Python with ast.parse; it never executes the code.
  • knowledge — exact-question lookup in a local knowledge base with question, answer, and optional source fields.
  • math — independent recomputation with a sealed certificate.

Third parties can register a verifier with mathcore.register_verifier(). Verifier failures are reported as UNVERIFIABLE, never silently skipped, and every verdict records which verifier decided it.

The checked-in trusted_kb/ tree authenticates curated content with SHA-256 manifests. A missing or mismatched manifest fails closed, so the knowledge verifier never certifies content it cannot authenticate. Verify a tree before trusting it:

python -m mathcore.trusted_kb verify trusted_kb

Updates you can verify

zoveli update --check reports whether a newer release exists; zoveli update downloads the archive, verifies its published SHA-256, and runs the same installer used for a manual install. Redirects are followed manually and restricted to HTTPS GitHub hosts on port 443, so a lookup cannot be redirected to localhost or another machine on your network.

Release builds publish a signed and notarized macOS .dmg and a signed Windows .exe. Portable installers also support --check / -Check for a read-only version report.

Your vault, your files

  • Memory database: ~/.zoveli/memory.db (override with ZOVELI_MEMORY_DB).
  • Markdown vault: ./knowledge-vault (override with ZOVELI_VAULT_PATH).
  • Audit log: ~/.mathcore/audit.jsonl (override with MATHCORE_AUDIT).

Backups include a SHA-256 manifest and can be verified offline:

pnpm vault:backup -- --out ./backups/2026-11-03
pnpm vault:verify -- ./backups/2026-11-03
pnpm vault:restore -- ./backups/2026-11-03 --force

Deleting your data is local and immediate: stop Zoveli, then remove the paths above. Backups you created elsewhere are not touched.

Honest limits

  • A cloud provider sees the chat content you send. Use local Ollama if that is not acceptable.
  • Web research makes network requests to the sites you name.
  • The audit chain detects edits; it is not a remote notarization service.
  • The code verifier checks syntax only — not behavior or security.
  • The knowledge verifier authenticates checked-in content against manifests, but anyone who can rewrite both the content and its manifest can change what it certifies. Treat the KB as code you review.
  • The public trust score measures the checked-in fixtures, not your own data or every possible question.

Read the full data-handling and recovery details in docs/TRUST.md. For vulnerability reports, see the security policy.
